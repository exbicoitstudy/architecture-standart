
| Код | Требования                                                                                                    | Комментарий                                                      |
|-----|---------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------|
| F   | Функциональные (Functionality)                                                                                |                                                                  |
| F1  | Клиент может просматривать список депозитов с актуальными ставками на сайте и в интернет-банке                | Важно поддерживать два канала сразу                              |
| F2  | Новый клиент может подать заявку на депозит через сайт, указав ФИО и телефон                                  |                                                                  |
| F3  | Сотрудник кол-центра может видеть заявку с сайта и позвонить клиенту для уточнения условий                    |                                                                  |
| F4  | После звонка клиент должен прийти в отделение для идентификации                                               | Законодательное требование                                       |
| F5  | Клиент интернет-банка может подать заявку на депозит онлайн, выбрав счет и сумму                              |                                                                  |
| F6  | Ставка для клиента в интернет-банке персонализирована                                                         | Требует интеграции с системой расчета ставок (пока Excel)        |
| F7  | Клиент подтверждает заявку через СМС-код                                                                      | Важно для безопасности                                           |
| F8  | Менеджер бэк-офиса подтверждает заявку и оформляет депозит в АБС                                              | На этапе MVP оформление не автоматизировано                      |
| F9  | Клиент получает СМС-уведомление о принятии заявки и успешном открытии депозита                                |                                                                  |
| U   | Удобство использования (Usability)                                                                            |                                                                  |
| U1  | Интерфейс сайта и интернет-банка соответствует дизайн-системе банка                                           | Согласован с брендбуком                                          |
| U2  | Все клиентские действия должны занимать минимум времени                                                       | Ожидание бизнеса                                                 |
| R   | Надёжность (Reliability)                                                                                      |                                                                  |
| R1  | Передача данных о заявках защищена шифрованием                                                                | Для обоих каналов                                                |
| R2  | Система должна быть доступна 24/7 с SLA не ниже 99.9%                                                         | Критично для цифрового сервиса                                   |
| R3  | В случае сбоя в основном ЦОД интернет-банк переключается на резервный                                         | Требует ручного или автоматического switchover                   |
| P   | Производительность (Performance)                                                                              |                                                                  |
| P1  | Время отклика на получение списка депозитов — не более 1 сек                                                  | Для хорошего UX                                                  |
| P2  | Решения должны поддерживать горизонтальное масштабирование для интернет-банка/сайта                           | Критично для роста                                               |
| S   | Поддерживаемость (Supportability)                                                                             |                                                                  |
| S1  | Решение должно быть реализовано на стекe, с которым уже знакома команда                                       | MS SQL, Oracle, .NET, React.js                                   |
| S2  | Необходимо вести документацию по интеграциям и бизнес-процессам                                               | Для последующего развития                                        |
| S3  | При доработке функций СМС использовать только внутренние ресурсы банка, без подрядчика                        | Чтобы MVP был реализуем                                          |
| +R  | + Ограничения (Restrictions)                                                                                  |                                                                  |
| +R1 | Не хранить ставки и заявки только в Excel — нужно вынести в централизованное хранилище                        | Рекомендуется реализовать в АБС или отдельном сервисе            |
| +R2 | Избегать прямой интеграции интернет-банка с АБС для заявок — использовать промежуточный сервис                | Снижает нагрузку и риски по SLA                                  |
| +R3 | Новые сервисы должны быть совместимы с текущими БД и языками (MS SQL/Oracle, .NET, PHP, React)                | Для ускорения разработки                                         |
| +R4 | Использовать только сертифицированные механизмы шифрования для передачи данных                                | Требование ИБ и законодательства                                 |
| +R5 | Если нужны очереди сообщений — предпочтительно использовать Kafka, если это поддерживается инфраструктурой.   | Текущий интернет-банк не поддерживает Kafka                      |
| +R6 | Для MVP заявки обрабатываются вручную в бэк-офисе, а не автоматически                                         | Требование бизнеса и ограничения ресурсов                        |
| +R7 | АБС поддерживает только вертикальное масштабирование                                                          | Из-за архитектуры и особенностей используемой базы данных        |
| +R8 | Новые сервисы должны поддерживать горизонтальное масштабирование                                              | Для обеспечения высокой доступности и возможности роста нагрузки |
| +R9 | Сайт и интернет-банк должны быть устойчивы к ошибкам сторонних сервисов (например, СМС-шлюза)                 | Обработка ошибок обязательна                                     |
